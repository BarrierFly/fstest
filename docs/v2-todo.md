# fstest v2 待办清单

本文件汇总规范 §十 中 v2 规划项，以及实现 v1 过程中发现、被有意推迟的改进。
按优先级分组；带 **[优化]** 的是纯成本/可读性改进，不改变测量语义。

## 一、优先做（直接影响可用性）

1. **配置持久化**
   - 现状：`FstestConfig` 全部字段（mode / color / counts / range / pstrategy / updates / duplications / targets）仅存内存，重启回落初始值。
   - 目标：落盘到 `<run-dir>/config/fstest.json`（或服务端 config 目录），启动时读取、`/fstest` 修改后写回；targets 与开关是重灾户（手工重输坐标很痛）。
   - 需定义：文件损坏/版本迁移的降级行为（读取失败回落默认值并告警）。

2. **按标记方块分组的 diff 输出**（规范 §九）
   - 现状：报告只按"结果种类"聚合（`=== Nx [标签] ===`），不按监测位置分组。
   - 目标：在聚合结果内再按 `pos` 分组，或提供按位置的视图，便于在多个 marker 的装置上定位问题来源。

3. **回归测试** [优化]
   - 现状：`gradle test` 为 `NO-SOURCE`，无任何自动化测试。
   - 目标：
     - 纯逻辑单测（不依赖 MC 运行时）：`Symmetry` 正/逆变换往返、方向映射、`DiffEngine`（顺序 vs 增删）、`OffsetSampler` 坐标合法性、`FstestConfig` 解析。
     - 黄金回放用例（规范 §十 v1.x）：录制一次真实操作，断言"0° 基线 == 现实"，防跨版本静默漂移；需要能在测试中起一个最小服务端，工程量较大，可后置。

## 二、规范已列的 v2 功能

4. **光照精确复制**：现在天空光恒 15 / 方块光恒 0，光敏元件（阳光探测器等）结果仅供参考。
5. **hashdelta 策略**：几何不动，拦截位置哈希输入并施加合法增量，把"纯哈希依赖"与"边界效应"分开验证；与已实现的"顺序差异分类"（`DiffEngine.orderOnly`）互补。
6. **JSONL 机器输出**：在现有纯文本日志之外增加结构化变体，便于外部脚本聚合/绘图。
7. **Stonecutter 多版本**：扩展 1.19.4 / 1.21.10 / 26.x；每个版本建立黄金回放回归用例（见 #3）。

## 三、可选的优化项 [优化]

8. **弹性区块加载**（规范 §六首选方案）：现在按 `/fstest range` 一次性快照；弹性加载可按影响传播按需取块，同时降低每轮世界构建成本。也是当前 P 次数下整体耗时的主要来源。
9. **聊天里的日志路径可点击**：现在是纯文本路径；可改为 [`open_file`](https://minecraft.wiki/w/Text_component_format) 点击组件。
10. **报告截断阈值可配置**：`ReportFormatter` 的 `MAX_DISTINCT_OUTCOMES` / `MAX_OPS_PER_OUTCOME`、`SimulationLog` 的 `MAX_HEADER_LABELS` 硬编码，可按需暴露为配置。
11. **分析耗时统计与预算**：分析同步跑在服务端线程，BOTH + 默认次数约 208 轮；建议在日志头记录总耗时、每轮 stats 记录单轮耗时，并可选加一个软预算（超时停排后续轮次并注明部分结果）。

## 四、明确不做（记录在案，避免误报 bug）

- `BlockEntity#preRemoveSideEffects` 不模拟（实体/掉落物/game event 在窗口外）——见 `tis-divergences.md` §三。
- 客户端渲染（box + 文本）不实现；只有聊天摘要 + 文本日志。
- 事件树/作用域模型：保持平铺事件流 + LCS 顺序对齐。
